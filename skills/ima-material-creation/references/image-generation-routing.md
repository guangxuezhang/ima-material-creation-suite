# 图片生成调度与质检

## 路由顺序

每个图片任务使用同一任务编号、最终提示词、参考图和输出目标，按以下通道规则执行：

1. 默认使用外置生图通道一 FriModel。
2. 只有用户明确说“用 laozhang 生图/切换 laozhang 通道”时，才使用外置生图通道二 laozhang。
3. 未经用户明确授权，不因 FriModel 失败而自动切换 laozhang；必要时报告失败并等待指令。
4. 通道失败时记录任务编号、通道、阶段与错误并汇报，不得假称仍在生成。

外置 GPT 与 Gemini 读取同一批本机令牌配置，但调用各自对应的模型接口。不得在提示词、日志、技能或交付中暴露令牌。

## 并发与状态

- 批量任务按独立图片数和可用外置线路数并行，任务数少于线路数时不得为占满线路而重复请求。
- 每张图拥有独立状态文件和输出路径。
- `failed` 或请求发送前失败才可进入下一线路。
- `running`、`succeeded`、服务端状态不确定的超时或 `timeout_needs_confirmation` 不得自动重复提交，以免重复计费。
- 单张失败不牵连整批成功任务；只补失败编号。
- 用户要求外置通道时，遵守 `external-image-channel` 的当前任务执行、保存和状态规则。

## 输出与质检

- 输出必须保存在当前任务目录并返回当前对话，不转发其他任务。
- 生图前必须完成逐篇逐页内容清单，不允许用固定通用页面文案直接批量发起请求。
- 按创作模式核验数量、比例、最终像素、中文准确性、真实截图、版式完成度、页面语义和跨篇近重复。
- 3:4 营销图片统一输出 1536×2048；模型返回其他严格 3:4 尺寸时可无裁切等比规范化。
- 生成联系表用于整组视觉检查，但联系表不是发布图片，也不能替代逐张原图的 OCR 与视觉检查。
- 真实产品截图固定采用直接输入融合：随提示词发送原截图并明确位置、设备边框和场景关系，由模型完成整体设计；除非用户明确要求，不自动切换为预留位后拼。
- 真实产品截图的跨设备来源、手机端与电脑端选择边界按 [product-screenshot-library.md](product-screenshot-library.md) 执行；不得依赖当前设备的本地素材路径。
- 技术成功不等于内容合格。只有 [quality-gates.md](quality-gates.md) 全部通过，才能进入交付。
